# Kaordo UI/UX audit — 1 October 2026

## Scope and method

Reviewed the implemented portal, registration and sign-in, Fluo feed/search/saved/profile/composer/post detail/media/replies, Ligo conversation list/composer/message actions, and the current Rondo/Regado landing screens. Future Rondo and Regado workflows are outside the score. Review used source inspection, automated Chromium screenshots, a complete local identity and product flow, axe-core WCAG 2.2 A/AA rules, reflow checks, keyboard interaction, and production builds. The automated flow creates and removes a temporary account and exercises TOTP, Ligo saved messages, Fluo media and post actions.

[ISO 9241-11:2018](https://committee.iso.org/standard/63500.html), confirmed in 2023, provides the effectiveness/efficiency/satisfaction framework in a specified context of use. [WCAG 2.2](https://www.w3.org/TR/WCAG22/) provides testable accessibility criteria. The [UEQ handbook](https://ueq-online.org/Material/Handbook.pdf) defines attractiveness, perspicuity, efficiency, dependability, stimulation, and novelty; [VisAWI](https://aupsy.uni-wuppertal.de/en/instrumente/visawi/) defines simplicity, diversity, colorfulness, and craftsmanship. None of these standards or instruments specifies a universal 0–100 UI quality score. The numbers below are an **equal-weight, expert heuristic** with a ceiling for missing evidence. They are not participant questionnaire results, ISO certification, or a complete WCAG conformance claim.

## Scores after changes

Each dimension has weight 1/12. Scores reflect the **implemented and tested** workflows, with deductions for evidence and product gaps. Arithmetic mean = 1153 / 12 = 96.08, rounded to **96/100**.

| Dimension | Score | Evidence and remaining limit |
| --- | ---: | --- |
| Usability | 96 | Automated task completion covers authentication, navigation, posting, saved content and messaging. No measured human completion rate. |
| UX | 95 | Post/reply/quote use one composition pattern; loading and retry states are explicit; feed position survives post detail. Perceived ease and satisfaction are unmeasured. |
| Visual aesthetics | 95 | Screenshot review shows a coherent palette, restrained surfaces, aligned action controls, and improved attachment previews. No VisAWI respondent ratings. |
| Consistency | 97 | Shared Tailwind/Rhea tokens and shadcn-svelte buttons, dialogs, menus and message primitives are reused across apps; a shared application header aligns branding. Keycloak screens remain separately themed. |
| Accessibility | 94 | Exercised axe WCAG A/AA scans pass after fixing Ligo timestamp contrast; keyboard and 320px checks pass. Author-provided video captions are absent, image descriptions remain optional, and screen-reader testing is missing. |
| Hierarchy | 97 | Each app has a clear heading and primary action; Fluo separates the feed, post detail, reply, quote and options; Ligo separates list, conversation and composer. |
| Typography | 96 | Shared Inter variable font and text tokens; small mobile navigation and Ligo metadata were enlarged. Long translated text and user font overrides need validation. |
| Spacing | 96 | Post actions, modal scroll areas and message controls have deliberate hit areas; single-media frames and attachment descriptions avoid unused or cramped space in tested states. |
| Colors | 97 | Centralized semantic tokens and settled-state axe contrast scans in light/dark. Ligo timestamp changed from translucent to full muted foreground after a measured 3.81:1 failure. |
| Navigation | 97 | Portal links to both working apps; Fluo mobile navigation keeps four frequent sections and Post visible while “More” exposes infrequent sections. Hash/back/escape post flow passes. |
| Feedback | 96 | Account, feed, message and media loading states; retry and destructive confirmation; upload/processing indicators; pending action states. No human comprehension study. |
| Responsiveness | 97 | Automated no-overflow checks at 320/768/1280px on public routes and 320/390px in core authenticated flows. Safari/Firefox, real touch devices and all zoom settings are untested. |

**Target status:** overall ≥99 and every dimension ≥95 are **not met**. Accessibility is 94, and the aggregate is 96. Claiming 99 would require closing the caption and descriptive-media gap plus representative task, screen-reader, browser/device, UEQ and VisAWI evidence. A passing axe scan alone does not prove WCAG conformance.

## Findings and changes

| Element / problem | Reference pattern | Kaordo change and verification |
| --- | --- | --- |
| Portal presented the implemented Ligo as future work | [shadcn-svelte Sidebar](https://shadcn-svelte.com/docs/components/sidebar) separates navigation structure, active state and responsive presentation | Portal now offers Fluo and Ligo as equal live destinations; Rondo and Regado remain plainly marked as future work. Public route test verifies the Ligo link. |
| App headings and cross-app navigation diverged | shadcn-svelte's composable navigation approach | Added `packages/ui/src/lib/AppHeader.svelte` and reused it in Fluo, Ligo and module landings; headings are semantic. Build and axe scans pass. |
| Seven Fluo destinations competed for 320px width | Frequent destinations stay directly reachable, with infrequent actions in an accessible menu | Four section buttons and Post remain in the bottom bar; Notifications and Settings move to a shadcn-svelte/Bits UI DropdownMenu. The authenticated mobile flow opens each destination and checks axe/reflow. |
| Search label promised people search, but only post search exists | Match control labels to actual capability | Search prompt and accessible name now say “Search posts”; the end-to-end search uses that label. |
| A private post reserved empty action space; replies looked detached from their parent | Reuse one action rhythm and a visible thread relationship | Private posts use a three-action grid; replies have a divider, author/time hierarchy and media labels. Post actions expose state and pending feedback. The end-to-end reply flow passes. |
| Fluo composer descriptions were squeezed into two columns on narrow screens | [Mastodon ComposeForm](https://github.com/mastodon/mastodon/blob/main/app/javascript/mastodon/features/compose/components/compose_form.jsx) keeps media upload, visibility, reply and quote context in the compose workflow | Below 420px, attachment previews become rows with full-width description fields; the action footer remains reachable. The 320px screenshot and publish flow pass. |
| Ligo loading state was visually blank; timestamps inside tinted bubbles lacked contrast | [Signal Desktop attachment utilities](https://github.com/signalapp/Signal-Desktop/blob/main/ts/util/Attachment.std.ts) classify visual/file attachments and bound timeline media sizes | Account gates show a clear loading state; Ligo keeps compact media/message controls. Timestamp opacity was removed and type enlarged. A real 3.81:1 axe failure is now absent in the saved-message test. |
| Fluo guest entry exceeded the initial 100 KiB gzip JavaScript budget | Load complex product UI after authorization when it becomes useful | `DeferredFluoApp.svelte` loads the feed only after the account gate resolves and supplies loading/retry states. The production bundle test passes. |

The existing product stack already uses Embla for galleries, PhotoSwipe for full images, Vidstack for video, Tiptap for writing, TanStack for data, shadcn-svelte/Bits UI for interaction, Tailwind for tokens and Lucide for icons. This pass added **no new runtime UI dependency**. The comparisons above informed concrete elements; they do not imply that copying another project's design guarantees usability.

## Framework interpretation and remaining work

- **ISO effectiveness:** automated flows demonstrate core tasks in the tested environment. **Efficiency:** fewer competing mobile destinations and deferred nonessential JavaScript, but no participant task timing. **Satisfaction:** unmeasured.
- **UEQ:** attractiveness maps to aesthetics; perspicuity to hierarchy/navigation; efficiency to usability/feedback; dependability to predictable states; stimulation/novelty to the visual experience. These are expert mappings only, not UEQ scale results.
- **VisAWI:** simplicity maps to reduced navigation and action density; diversity to differentiated content; colorfulness to semantic palette; craftsmanship to alignment, crop behavior and feedback. No questionnaire was administered.
- **WCAG:** automated A/AA checks cover selected states. Add a caption track authoring/storage/playback flow for video, decide how nondecorative image descriptions are required, and conduct keyboard/screen-reader reviews with assistive technology. Test 200%/400% zoom, Safari, Firefox, real mobile safe areas and longer content before a conformance claim.
