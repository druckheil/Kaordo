# UI and UX audit — 1 October 2026

> Historical assessment of the tree and scope at the stated date. Scores, paths and deployment gaps describe that assessment, not the current refactored tree. See [the 3 October 2026 refactor review](../refactoring.md) and [current architecture](../architecture.md) for updated ownership, capabilities and verification.

## Scope and scoring

This audit covers the implemented registration, sign-in, portal, Fluo feed, search, saved posts, profile, post composer, media, quotes, replies, reactions, and deletion. The other apps have landing screens but no comparable product workflows yet. Their future features are excluded from the score.

[ISO 9241-11](https://www.iso.org/standard/63500.html) frames usability as effectiveness, efficiency, and satisfaction in a specified context. [WCAG 2.2](https://www.w3.org/TR/WCAG22/) provides testable accessibility criteria. The [UEQ handbook](https://ueq-online.org/Material/Handbook.pdf) and [VisAWI research](https://www.sciencedirect.com/science/article/pii/S1071581910000777) supply experience and visual-aesthetic dimensions. None defines a universal 0–100 product score. Scores below are an equal-weight expert assessment, rounded to the nearest integer. They are **not** ISO/UEQ/VisAWI survey results or a WCAG conformance claim.

Evidence comprises code review, automated screenshots, Playwright interaction at 1280×720, 390×844, and 320×768, keyboard checks, axe-core rules tagged WCAG 2.0/2.1/2.2 A/AA, API/database checks, and the production frontend build. No participant study, screen-reader session, cross-browser matrix, or measured task timing was performed. These gaps cap confidence in perceived UX, aesthetics, and accessibility. A 320 CSS-pixel viewport exercises narrow layout, but it does not prove behavior at every zoom setting.

**Normalized UI/UX Quality Score: 95/100** (1144 ÷ 12 = 95.33, rounded). The requested ≥99 and no dimension below 95 are **not achieved**. This score is an expert proxy with evidence, not a claim that the interface is ideal or free of every defect.

ISO effectiveness has automated task evidence; efficiency has fewer steps and no nested feed scroll, but no measured human task time; satisfaction is unmeasured. UEQ attractiveness, perspicuity, efficiency, dependability, stimulation, and novelty informed the visual, usability, navigation, feedback, and UX rows. VisAWI simplicity, diversity, colorfulness, and craftsmanship informed hierarchy, aesthetics, colors, and consistency. These are mappings for review, not questionnaire responses.

## Changes and reproducible evidence

| Problem found | Change and check |
| --- | --- |
| The post detail grew after opening when image dimensions arrived | [FluoDialogs](../../apps/fluo/src/lib/FluoDialogs.svelte) waits for post data or an error before mounting the dialog. The live test holds the post request and checks that the detail dialog is absent until data is ready. The modal now fades without zoom scaling. |
| A single image left excess space in post detail; multiple media could widen the dialog | Dialog width is derived from stored media dimensions, while its inner grid clips horizontal overflow. The live test checks that the detail is wider than a feed card and that a four-image gallery stays inside its bounds. |
| The native scrollbar crossed rounded modal corners | Dialog shells clip overflow; their inset scroll containers use the shared thin `kaordo-scrollbar`. The live test checks scrollbar width, inset, and clipping. |
| Long composer content moved primary actions out of reach | [Composer](../../apps/fluo/src/lib/Composer.svelte) reserves editor height and keeps its action footer sticky inside a scrollable dialog. At 320px the media, options, and publish controls remain in one 44px-high row; the four-attachment composer is checked for overflow and axe violations. |
| Floating mobile Post control overlapped feed actions | [FluoApp](../../apps/fluo/src/lib/FluoApp.svelte) puts Post in the first mobile navigation cell. Labels stay visible at 320px. |
| Browser deletion prompt broke the visual system and nested modal flow | A shadcn-svelte confirmation dialog now shows the consequence, pending state, and inline error. The live test cancels deletion from an open post and verifies the same post remains available. |
| Media layout estimates caused feed remeasurement | [media-layout](../../packages/media-ui/src/media-layout.ts) calculates reserved height from stored dimensions and the same gallery gap; three unit cases cover single, multi-portrait, and extreme ratios. Window virtualization uses this estimate. |
| Uploaded media lacked author descriptions | Each attachment has an optional description field. Kerno validates and stores it per post attachment, and feed/quote media uses it as accessible text. The live test checks persistence and quote reuse. |
| Returning from post detail could lose the feed position | Fluo stores the scroll position when the post opens and restores it on browser Back or the in-app Back action. The live test exercises both after a nested confirmation dialog. |

The media interface reuses Embla for the gallery, PhotoSwipe for image viewing, Vidstack for video playback, Tiptap for editing, Bits UI through shadcn-svelte for dialogs, and Lucide icons. No additional UI dependency was needed in this pass.

## Remaining evidence and product gaps

1. Add author-managed video captions and decide how image descriptions should be required or explicitly marked decorative. Optional descriptions improve authoring but do not ensure every published post meets WCAG 1.1.1; video without captions does not establish WCAG 1.2.2 conformance.
2. Run representative ISO task sessions and actual UEQ/VisAWI questionnaires before assigning high-confidence satisfaction or aesthetics scores. Test with screen readers, keyboard-only use, zoom, and dark theme.
3. Exercise Safari and Firefox, tablet widths, long posts, slow media, and varied browser safe areas. The passing Chromium flow is evidence for those exercised paths only.
