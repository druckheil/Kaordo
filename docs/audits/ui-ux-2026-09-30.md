# UI and UX audit — 30 September 2026

## Scope and method

This review covers the implemented registration and sign-in flow, portal, Fluo feed, post creation, media viewing, reactions, replies, saved posts, search, profile, and the visible landing screens for the other apps. It does not grade future Ligo, Rondo, or Regado features as if they were shipped.

[ISO 9241-11](https://www.iso.org/standard/63500.html) defines usability through effectiveness, efficiency, and satisfaction in a specified context. [WCAG 2.2](https://www.w3.org/TR/WCAG22/) supplies testable accessibility criteria. The [UEQ handbook](https://ueq-online.org/Material/Handbook.pdf) and the [original VisAWI work](https://www.sciencedirect.com/science/article/pii/S1071581910000777) inform the experience and visual heuristics. None of these publications defines a universal 0–100 product score. The scores below are an explicit, equal-weight expert rubric for this repository, not an ISO, WCAG, UEQ, or VisAWI certification. No participant completed a UEQ or VisAWI questionnaire.

Evidence: source inspection; headless Chrome at 1280×720, 390×844, and 320×768; automated screenshots of registration, portal, feed, comments, and mobile feed; end-to-end registration, TOTP, media posting, carousel, replies, reactions, saved posts, search, SSO, and deletion; axe-core rules tagged WCAG 2.0/2.1/2.2 A/AA on the exercised screens. The screenshots are generated by `KAORDO_UI_SNAPSHOTS=1 pnpm test:auth:live` outside the repository. Automated accessibility checks cannot establish full WCAG conformance.

ISO effectiveness has automated task evidence, but no human completion rate. Efficiency improved by removing the extra identity click, nested scrolling, and separate reply navigation; no human task time was measured. Satisfaction is unmeasured. UEQ's attractiveness, perspicuity, efficiency, dependability, stimulation, and novelty are reflected respectively in the aesthetics, usability/hierarchy, navigation, feedback, UX, and aesthetics rows below. VisAWI's simplicity, diversity, colorfulness, and craftsmanship are reflected in hierarchy, aesthetics, colors, and consistency. These mappings are expert observations, not survey results.

## Result

| Dimension | Score / 100 | Verified evidence and remaining limit |
| --- | ---: | --- |
| Usability | 91 | Registration and sign-in go directly to the identity form; publishing, saving, replying, quoting, and deleting pass the live task flow. Task completion by actual users is unmeasured. |
| UX | 90 | A compact editor leaves the feed visible until focus and previews selected media; inline replies, one page scroll, cached session preview, visible pending states, and reduced motion support remove observed interruptions. UEQ perception by users is unmeasured. |
| Visual aesthetics | 93 | Shared surfaces, rounded cards, restrained green palette, coherent identity theme, and carousel were inspected in captured screens. VisAWI scores by users are unmeasured. |
| Consistency | 95 | [Shared tokens](../../packages/ui/src/lib/styles.css), [buttons](../../packages/ui/src/lib/components/ui/button/button.svelte), [post actions](../../apps/fluo/src/lib/PostCard.svelte), and the [Keycloak theme](../../deploy/keycloak/themes/kaordo/login/resources/css/kaordo.css) now follow one visual system. Native select and third-party media controls retain some platform styling. |
| Accessibility | 89 | axe-core reports no A/AA violations in exercised desktop and mobile states; keyboard activation of the carousel and focus access to dislike pass, and controls have names and reduced motion support. Uploaded images still lack author-written alternative text; video captions and manual screen-reader testing remain absent. |
| Hierarchy | 95 | App header, page heading, feed order, composer, post, and reply levels are visually distinct; empty states direct users to a next step. |
| Typography | 94 | Shared Inter font and consistent title/body/meta scale. Six-item mobile navigation uses 10px labels above 375px; below that it shows accessible icon-only actions to avoid overlapping text. |
| Spacing | 95 | Shared control sizes and consistent card, action, and reply spacing; the feed scrolls with the document instead of inside a nested pane. |
| Colors | 95 | Semantic light/dark tokens, state colors, and focus color are centralized; axe contrast checks pass on exercised light-theme screens. Dark-theme renderings were not exercised. |
| Navigation | 93 | Desktop sidebar, mobile bottom bar, hash navigation, and portal app entry work; notifications and settings are explicitly limited screens. No cross-device user task study exists. |
| Feedback | 94 | Account, editor, upload, publish, page load, comments, error, and retry states are visible. Long-running task comprehension has not been tested with users. |
| Responsiveness | 95 | 320px and 390px feeds have no horizontal overflow; mobile navigation remains fixed at the bottom, and media is constrained to card width. Tablet widths and browser zoom need further coverage. |

**Normalized UI/UX Quality Score: 93/100** (arithmetic mean of the twelve dimension scores, rounded). The requested ≥99 and every dimension ≥95 are **not verified or achieved**. The largest concrete gap is accessible author-supplied media descriptions and captions. Perceived satisfaction and aesthetics also require real participants before a 99 claim would be credible.

## Changes made in this pass

| Earlier issue | Current implementation and evidence |
| --- | --- |
| A separate continue click preceded the identity form | [AuthScreen](../../apps/portal/src/lib/AuthScreen.svelte) initializes Keycloak and opens login or registration on arrival, with a safe Back fallback. The live test asserts direct arrival at the form. |
| Feed had an independently scrolling pane | [FluoApp](../../apps/fluo/src/lib/FluoApp.svelte) uses window virtualization and document scrolling; the main page supplies a sticky app header. |
| Multiple attachments had no carousel | [MediaGallery](../../apps/fluo/src/lib/MediaGallery.svelte) uses MIT-licensed Embla 8 for arrows, dots, and swipe, with PhotoSwipe for images and Video.js for video. The live test posts four images and changes slides. |
| Image height changed when media loaded | Media width and height were already persisted in the Fluo metadata model; the gallery now reserves their aspect ratio before image decoding. The live test compares the carousel box to the stored 8×6 ratio. |
| Post actions and replies looked disconnected | [PostCard](../../apps/fluo/src/lib/PostCard.svelte) gives actions equal positions, places dislike behind hover or keyboard focus (visible on touch), and expands comments and the reply composer directly under the post. |
| The editor dominated the first mobile screen and uploads showed only filenames | [Composer](../../apps/fluo/src/lib/Composer.svelte) initially shows a compact prompt and media action, expands on focus without an extra click, and previews removable image/video attachments. |
| Controls and app surfaces had inconsistent visual weight | [Shared UI](../../packages/ui/src/lib/styles.css), [portal](../../apps/portal/src/routes/+page.svelte), [account gate](../../packages/account-ui/src/AccountGate.svelte), and [module landing](../../packages/ui/src/lib/ModuleLanding.svelte) use one palette, radius scale, and spacing system. |
| Small screens could overflow horizontally | The media viewport is explicitly constrained to its card; 320px and 390px live assertions pass. |

## Validation and open evidence

- `pnpm check:front`: six Svelte projects, zero errors and warnings.
- `pnpm test:auth`: 31 passed.
- `pnpm test:dependencies`: 26 passed.
- `pnpm test:pages`: five passed, including static artifact and Fluo initial bundle budget.
- `KAORDO_UI_SNAPSHOTS=1 pnpm test:auth:live`: full flow passed, including four attachment previews, removing/readding one, keyboard carousel/dislike checks, desktop and mobile axe scans, and 320px/390px overflow checks.
- `pnpm audit --audit-level=low`: no known vulnerabilities reported at review time. The newly added Embla and Tiptap Placeholder packages declare MIT licenses.

To raise the accessibility score, the post API and composer need author-provided image descriptions and video captions, followed by keyboard, zoom, and assistive-technology sessions. To measure ISO effectiveness/efficiency and UEQ/VisAWI satisfaction, run representative tasks and the actual questionnaires with users; source inspection cannot substitute for those measurements.
