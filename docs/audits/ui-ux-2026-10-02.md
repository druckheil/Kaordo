# Kaordo UI/UX audit — 2 October 2026

> Historical assessment of the tree and scope at the stated date. Scores, paths and deployment gaps describe that assessment, not the current refactored tree. See [the 3 October 2026 refactor review](../refactoring.md) and [current architecture](../architecture.md) for updated ownership, capabilities and verification.

## Scope and scoring

This review covers the **implemented** portal, Keycloak registration/sign-in/TOTP, Fluo, Ligo, and Rondo. Regado is a clearly marked landing page, so its future workflows are excluded. The review used source inspection, automated Chromium screenshots, keyboard and task flows, axe-core WCAG 2.2 A/AA scans, and layout checks. It did not use manual website exploration.

[ISO 9241-11](https://www.iso.org/standard/63500.html) evaluates effectiveness, efficiency, and satisfaction in a context of use. [WCAG 2.2](https://www.w3.org/TR/WCAG22/) supplies testable accessibility criteria. The [UEQ handbook](https://ueq-online.org/Material/Handbook.pdf) and [VisAWI](https://aupsy.uni-wuppertal.de/en/instrumente/visawi/) define respondent-based experience and visual-aesthetic scales. None defines a universal 0–100 quality score. The scores below are an **equal-weight expert assessment** of the tested product, with deductions for missing evidence. They are not ISO certification, UEQ/VisAWI survey results, or a WCAG conformance claim.

## Changes and rationale

| Finding                                                                             | Change                                                                                                                                   | Evidence                                         |
| ----------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------ |
| App headers had no direct keyboard path to content                                  | Added a visible-on-focus skip link and focusable main targets across the portal, Fluo, Ligo, Rondo, and module landings                  | Public keyboard test and Svelte check            |
| Portal's introduction pushed app actions down                                       | Reduced hero height and card spacing so Fluo, Ligo and Rondo actions are visible in the first 1280×720 viewport                          | Automated screenshot review                      |
| Ligo showed an empty-chat prompt even when Saved messages existed                   | Empty state now respects the saved conversation; filtered member searches distinguish existing members from no matches                   | Authenticated flow and code review               |
| Dialog titles and content changed while the previous dialog was closing             | Kept the last Ligo/Rondo dialog mode and Fluo composer context through the close animation                                               | Authenticated dialog checks                      |
| Rondo panel toggles lost keyboard focus; mobile members acted like a visual overlay | Restore focus to the replacement toggle; use the existing shadcn-svelte/Bits UI Dialog for mobile members, with focus trap and dismissal | Authenticated focus/axe checks                   |
| Rondo's narrow channel header compressed its title and voice badge                  | Reflowed title and action into separate rows on narrow screens; kept live-video previews compact                                         | 320px geometry assertion, light/dark screenshots |
| A stale route test treated implemented Rondo as a placeholder                       | Updated prerendered-route assertions to check Rondo's authenticated gate and portal navigation                                           | Pages test 5/5                                   |
| Ligo declared a direct media UI dependency it did not import                        | Removed the unused declaration; `chat-ui` still declares and uses the media component directly                                           | Dependency test 51/51                            |

This pass uses the existing **STaSBLR** components and tokens. No new runtime UI library was added. Media views continue to use the project's existing media components and stored dimensions; the changes do not replace them with duplicate carousel or modal code.

These comparisons informed interaction choices; they do not substitute for testing Kaordo with its own users.

## Limits before a 99 claim

Add a complete caption authoring/storage/playback path for prerecorded video and a useful-image-description policy; verify representative tasks with screen readers and keyboard only; test Safari, Firefox, real touch devices, zoom and large font settings; and collect actual task, UEQ and VisAWI responses from target users. A real multi-user Rondo call and screen-share flow also need device-level validation. Those checks could change the scores in either direction. No Critical or High UI issue was confirmed in the **tested** states; this is not evidence that none exist elsewhere.
