# Kaordo voice client

Shared LiveKit room/track lifecycle for Rondo. `connection` connects/disconnects, controls microphone/camera/screen capture, switches active devices through LiveKit and applies input/output volume. `participant-state` projects SDK participants/tracks into stable presentation values. The public entry point preserves the connection API; the `model` subpath exposes snapshots/types without loading LiveKit. Microphone volume uses LiveKit's audio processor lifecycle before publication, including track restarts. Output volume covers participant microphones, screen audio and interface sounds.

The `preferences` subpath validates browser defaults without loading LiveKit. `devices` exposes LiveKit device discovery, browser output authorization and an isolated cancellable microphone level check. The `sounds` subpath supplies optional local interface sounds and a speaker check, routed through a media element to the selected output. Device checks stop tracks, animation frames and audio contexts on disposal; they never publish to a room. Speaker checks own their completion timer. Connection teardown is idempotent, and disposed sounds cannot reopen audio contexts after late asynchronous work. Selected defaults are local to this browser, not server account settings.

Kerno authorizes channel membership and supplies the short-lived room token. Browser views attach/detach tracks using LiveKit and observe native fullscreen changes. Presets request capture resolution/frame rate; they cannot override browser/source/network limits. Credentials stay on the server and live tracks are not uploaded to Nodo. Calls are not E2EE.

The live journey checks room joining and synthetic camera controls. Real devices, remote multi-party quality and external TURN paths require separate validation. See [Rondo](../../apps/rondo/README.md) and [refactor evidence](../../docs/refactoring.md).
